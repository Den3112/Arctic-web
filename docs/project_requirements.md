## Технічне завдання

Необхідно розробити веб-додаток для обліку робочого часу (Time Tracker).

### 1. Обов’язковий функціонал

#### Основний трекер часу

- Кнопка **Start/Stop** для початку та завершення відліку часу.
- Поле введення **назви задачі** (бажано з автодоповненням раніше введених задач).
- Вибір **проекту** (або клієнта) зі списку.
- Відображення **активного таймера** (скільки часу пройшло з моменту натискання Start).
- Активний таймер має бути видно, навіть якщо користувач переходить на інші сторінки (якщо це SPA).

#### Управління задачами (Time Entries)

- Список записів за **сьогодні**.
- Можливість **редагувати** назву задачі та проект після створення.
- Можливість **змінити час** вручну (start time, end time).
- Кнопка **видалення** запису.
- Групування записів по днях (або хоча б просте розділення "Сьогодні" / "Вчора").

#### Управління проектами

- Створення нового проекту (Назва, Колір).
- Редагування існуючих проектів.
- Колір проекту має відображатися біля задач у списку.

#### Звіти (Reports)

- Проста сторінка зі статистикою.
- Відображення загального часу за **День / Тиждень / Місяць**.
- Діаграма (Pie Chart або Bar Chart) розподілу часу по проектах.
- Експорт даних у **CSV**.

### 2. Вимоги до технічної реалізації

- **AI-First Developer Approach:** Код повинен бути написаний з використанням AI (Cursor, Windsurf, v0, Replit Agent, ChatGPT etc.). Ручне написання коду зводити до мінімуму (тільки правки конфігів або фікс багів, які AI не може вирішити).
- **Лог промптів:** (Опціонально, але буде плюсом) Зберегти історію основних промптів або надати файл `PROMPTS.md`, щоб ми оцінили ваш підхід до роботи з LLM.

### 3. Архітектура та Деталі

- **Чистий код:** Структура проекту має бути зрозумілою (окремо компоненти, окремо хуки/логіка, окремо API).
- **State Management:** Використання React Context, Redux, Zustand або React Query для управління станом (список задач, активний таймер).
- **Data Persistence:** Дані повинні зберігатися в базі даних (Supabase, Firebase, SQLite, Vercel Postgres). LocalStorage підходить тільки для чорнетки, але для тестового краще повноцінна БД.

### 4. Стек технологій (рекомендований)

- **Frontend:** React / Next.js (App Router).
- **UI:** Tailwind CSS (Shadcn/UI або V0.dev generation).
- **Backend:** Next.js API Routes або Server Actions.
- **Database:** Supabase / Postgres / SQLite.
