# Fix UI Bugs: Mobile Menu, Background Performance, and Reports Layout

**Date:** 2026-02-15 14:45
**Files:**

- src/components/layout/Navbar.tsx
- src/app/globals.css
- src/components/features/ReportsView.tsx

**Severity:** medium

## Problem

Multiple UI issues identified:

1. **Mobile Menu:** The menu was fixed height without scrolling, causing items to be inaccessible on small screens.
2. **Performance:** Heavy background "blob" animations caused lag on mobile devices.
3. **Reports:** The Pie Chart container was too tall on mobile, and the table cells wrapped awkwardly, breaking the layout.

## Root Cause

1. Missing `overflow-y-auto` and specific height constraints on the mobile menu container.
2. The CSS `filter: blur(140px)` animation is computationally expensive and runs by default on all devices.
3. Hardcoded heights in chart containers and lack of `whitespace-nowrap` on table cells allowed content to break visually.

## Solution

1. **Navbar:** Added `fixed inset-0 top-16` positioning with `overflow-y-auto` to the mobile menu. Added `[FIX]` logging.
2. **Globals:** Added `@media (max-width: 768px) { display: none }` to `.bg-blob` to disable specific heavy animations on mobile.
3. **Reports:**
   - Modified chart container to use responsive height (`min-h-[350px] md:min-h-[400px]`).
   - Added `whitespace-nowrap` to table cells to force horizontal scrolling (`overflow-x-auto`).
   - Added `[FIX]` logging for chart interactions.

## Prevention

- **Responsiveness:** Always test menus with limited height/viewport. Use `dvh` units or `inset` positioning.
- **Performance:** Disable heavy CSS filters/animations on mobile by default.
- **Tables:** Use `whitespace-nowrap` for data tables to preserve alignment, relying on horizontal scroll.
