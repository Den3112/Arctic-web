# Patch: Fix Mobile Menu Persistence on same-page Navigation

**Date:** 2026-02-15 21:35
**Files:** src/components/layout/Navbar.tsx
**Severity:** medium

## Problem

The mobile menu remained open after a user clicked a navigation link that pointed to the CURRENT page (e.g., clicking 'Timer' when already on the dashboard).

## Root Cause

1. **Same-page Navigation**: Next.js doesn't trigger a full layout re-render or a `pathname` change event when clicking a link that resolves to the current URL.
2. **Missing State Reset**: The internal `isMobileMenuOpen` state was not being reset on the click event itself after a previous refactor favored `pathname` monitoring.

## Solution

1. **Dual State Management**: Re-added explicit `onClick` handlers to mobile menu links to ensure immediate closure.
2. **Render-phase Sync**: Maintained the `pathname` check in the component's render body to handle cross-page navigation gracefully without relying solely on click events (robustness fallback).
3. **Invalid HTML Removal**: Converted nested interactables to a single clickable block where appropriate to ensure clean event propagation.

## Prevention

- **Overlays need explicit signals**: For UI overlays like mobile menus, always include an explicit `onClick={() => setOpen(false)}` on links, even if you also monitor navigation events. This covers the "click same page" edge case.
